# Migraine AI - MVP спецификация

## 1. Цель MVP
Сделать веб-приложение "Календарь мигрени", где пользователь:
- входит в аккаунт;
- видит календарь 6x7 на месяц;
- видит приступы на календаре с учётом времени начала/конца;
- создаёт/редактирует приступ;
- получает автозаполнение нового приступа из последнего.

MVP ограничиваем одним языком интерфейса (RU) и одним часовым поясом пользователя.

## 2. Стек и архитектура
- Backend: PHP 8.3 + Laravel 11 (API-first)
- Frontend: Vue 3 + Vue Router + Pinia, без TypeScript
- DB: PostgreSQL 16
- Web: Nginx
- Auth: cookie-based session (Laravel Sanctum)

Почему так:
- Laravel ускорит реализацию auth/валидаций/миграций/тестов.
- Vue соответствует предпочтению и удобен для календаря.

## 3. Область MVP (in-scope)
### 3.1 Экран входа
- Если пользователь не авторизован -> `/login`.
- После успешного входа -> `/calendar`.

### 3.2 Календарь
- Сетка 6 строк x 7 дней.
- Навигация по месяцам (предыдущий/следующий).
- Внутри дня отображаются сегменты приступов:
  - левое скругление у начала приступа;
  - правое скругление у конца;
  - без скругления, если продолжение на соседний день.
- Горизонтальная позиция внутри дня зависит от времени:
  - `x = (minutes_from_00_00 / 1440) * 100%`.
- Цвет сегмента зависит от интенсивности (1-10):
  - 1-3 зелёный, 4-6 жёлтый, 7-8 оранжевый, 9-10 красный.

### 3.3 Создание приступа
- Клик по дню открывает `/attacks/new?date=YYYY-MM-DD&ratio=0..1`.
- Предустановка `start_at`:
  - если выбран сегодняшний день -> текущее время;
  - иначе `time = ratio * 24h` (пример 0.5 -> 12:00).
- При открытии формы система подтягивает последний приступ пользователя и предзаполняет поля, кроме дат/времени.

### 3.4 Редактирование приступа
- Клик по сегменту приступа в календаре -> `/attacks/:id/edit`.
- Пользователь может изменить любые поля.

### 3.5 Верхняя панель
- Кнопки: `Календарь`, `Графики`.
- В MVP `Графики` = заглушка с текстом "Раздел в разработке".

## 4. Out of scope (после MVP)
- SSR/SEO оптимизация.
- Продвинутые графики и аналитика.
- Импорт/миграция со старой системы.
- Мультиаккаунт/роли/совместный доступ.
- Уведомления и мобильное приложение.

## 5. Модель данных

## 5.1 Таблица users
- `id` (bigint, PK)
- `name` (varchar 120)
- `email` (varchar 190, unique)
- `password_hash` (varchar 255)
- `timezone` (varchar 64, default `Europe/Moscow`)
- `created_at`, `updated_at`

## 5.2 Таблица attacks
- `id` (bigint, PK)
- `user_id` (FK -> users.id, index)
- `start_at` (timestamp with time zone, index)
- `end_at` (timestamp with time zone, index)
- `intensity` (smallint, 1..10)
- `medications` (text, nullable)
- `relief` (boolean, nullable) - помогло ли лечение
- `pain_types` (jsonb) - массив значений
- `localizations` (jsonb) - массив значений
- `triggers` (jsonb) - массив значений
- `symptoms` (jsonb) - массив значений
- `auras` (jsonb) - массив значений
- `notes` (text, nullable)
- `created_at`, `updated_at`

Ограничения:
- `end_at > start_at`
- все enum-like значения валидируются на API уровне по белому списку.

## 5.3 Справочники (константы в коде MVP)
Храним как константные списки на backend + frontend (один источник через API `/meta/options`).

## 6. API (v1)
Префикс: `/api/v1`

### Auth
- `POST /auth/login` - email/password
- `POST /auth/logout`
- `GET /auth/me`

### Meta
- `GET /meta/options` - pain types, localizations, triggers, symptoms, auras

### Attacks
- `GET /attacks?from=YYYY-MM-DD&to=YYYY-MM-DD`
  - возвращает приступы пользователя, пересекающие интервал
- `GET /attacks/last`
  - последний приступ пользователя
- `POST /attacks`
- `GET /attacks/{id}`
- `PUT /attacks/{id}`
- `DELETE /attacks/{id}` (soft delete в MVP не нужен, hard delete)

## 7. Валидации
- `start_at`, `end_at` обязательны.
- `end_at` позже `start_at`.
- `intensity` целое 1..10.
- Все значения массивов только из допустимого словаря.
- Максимум 2000 символов в `notes`.

## 8. Правила отображения приступов в календаре
Для каждого дня D и приступа A:
- `segment_start = max(A.start_at, D 00:00)`
- `segment_end = min(A.end_at, D 24:00)`
- если `segment_start < segment_end`, рисуем сегмент.
- offset `%` = минуты от `D 00:00` до `segment_start` / 1440 * 100
- width `%` = длительность сегмента в минутах / 1440 * 100
- скругления:
  - left-radius, если `segment_start == A.start_at`
  - right-radius, если `segment_end == A.end_at`

## 9. Приёмочные критерии MVP
1. Неавторизованный пользователь всегда попадает на `/login`.
2. Авторизованный пользователь видит календарь 6x7.
3. Приступ, идущий через полночь, визуально разбивается на 2+ дневных сегмента корректно.
4. Клик по дню предзаполняет время по правилу today/ratio.
5. Новая форма предзаполняется данными последнего приступа (кроме дат/времени).
6. Можно создать, отредактировать и удалить приступ.
7. Данные разных пользователей изолированы.

## 10. План тестирования
### Unit
- проверка расчёта offset/width сегментов;
- проверка валидаций DTO/Request.

### Integration
- API тесты CRUD `attacks` + авторизация.

### System (e2e)
- сценарий: login -> календарь -> создание -> редактирование -> удаление.

### Acceptance
- ручной чек по 7 приёмочным критериям из раздела 9.

## 11. План реализации (итерации)
### Итерация 1 (backend foundation)
- Laravel проект, auth, миграции `users/attacks`, `meta/options`.

### Итерация 2 (calendar + form)
- Vue SPA, роутинг, страница календаря, форма создания/редактирования.

### Итерация 3 (полировка)
- визуальные состояния, тесты, docker-compose, nginx конфиг.

## 12. Риски и решения
- Риск: слишком широкий список симптомов и опций.
  - Решение: хранить в jsonb + централизованный словарь.
- Риск: сложная отрисовка длинных приступов.
  - Решение: единый pure-функциональный алгоритм сегментации + unit тесты.
- Риск: размытый scope.
  - Решение: держаться только раздела In-scope до завершения MVP.
